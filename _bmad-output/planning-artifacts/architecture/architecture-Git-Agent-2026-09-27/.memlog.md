- (decision) Subagent invocation is one-shot/stateless (matches Claude Code's documented orchestrator-worker pattern: workers can't AskUserQuestion, report once to orchestrator). All 5 skills follow a propose-then-execute shape: skill calls subagent for read-only analysis/plan, skill runs ALL user interaction (AskUserQuestion) in the main conversation relaying raw decisions (never parsing/mutating the subagent's plan structure itself), then skill calls subagent a second time to execute with user's decisions as plain input. Binds FR-1,FR-3,FR-4,FR-9 (all flows needing mid-flow user interaction). Prevents: skill absorbing git-domain logic (parsing/editing diffs, plans) which would blur the skill/subagent split the PRD's glossary and SM-1 depend on.
- (decision) Branch-parent tracking is cut entirely (resolves PRD Open Question 2). Create-PR (FR-8) always defaults its target branch to the repo's configured default PR target branch (from config file), and asks/lets the user override if they want a different target. No per-branch parent state is recorded anywhere (no git config, no state file, no derivation heuristic). Binds FR-8. Prevents: a parent-tracking mechanism (storage format, staleness on rename/delete, orphaned entries) with no real payoff over just defaulting + override.
- (question) PRD FR-8 and Open Question 2 describe branch-parent detection as the mechanism for defaulting create-PR's target branch; this run has scrapped that mechanism in favor of always defaulting to config's default target branch with user override. PRD text (FR-8's Consequences, Open Question 2, its Notes line) should be updated to match before/alongside spine finalization to avoid the PRD and spine diverging.
- (decision) FR-10 re-install behavior: confirmed as PRD's stated assumption. Re-running npx setup against an already-configured repo detects the existing config file, shows current values, and asks for confirmation before overwriting (full re-ask of setup questions, not per-field edit). Resolves PRD Open Question 4.
- (decision) A sixth skill, 'configure', is added to v1 scope to let the user redo the per-repo config (task/branch types, default PR target) without re-running the npx installer. Binds FR-10, FR-11. Prevents: re-configuration only being reachable through the installer/re-install flow.
- (question) PRD MVP Scope (6.2 Out of Scope) states 'Any second subagent or skill beyond the five named — additions here are explicitly a v2+ conversation.' This run adds a sixth skill ('configure') to v1, directly reversing that line. PRD sections needing update: 4.6 (add a configure skill description/FR), 6.1 In Scope (six skills, not five), 6.2 Out of Scope (remove or narrow the 'no skill beyond the five' line).
- (decision) The git subagent is a standalone Claude Agent SDK program (real code, not a .claude/agents/*.md declarative subagent), shipped as part of the npm package installed via npx. Each of the 6 skills (conversational, running as native Claude Code skills in the user's interactive session) launches this subagent as a subprocess (e.g. via the skill's Bash tool) and communicates over stdio with a structured (JSON) contract. The subagent's own query()/ClaudeSDKClient call defines its own tools, system prompt, and PreToolUse hooks in code via options.hooks -- this is where the no-force-push guarantee (FR-6) lives: an in-process hook scoped only to the subagent's own SDK session, never touching the user's Claude Code settings.json/settings.local.json, and never affecting the user's own manual terminal use or unrelated Claude Code sessions. The subagent reuses the existing installed CLI's auth (SDK's default transport shells out to the CLI), so no separate credential store is introduced (holds NFR 'uses existing repo setup only'). Binds: all FRs, especially FR-6 (hook lives in subagent code, not Claude Code hook config), FR-1/3/4/9 (skill<->subagent invocation contract). Prevents: force-push protection being global to any Claude Code session in the repo (settings.json/settings.local.json scoping problem) instead of scoped to only this program's own agentic loop.
- (decision) Configure skill (the 6th skill) reads/writes the per-repo JSON config file directly itself -- no subagent invocation. Rationale: config I/O isn't git/GitHub work; the subagent's scope stays limited to what the PRD glossary defines it as ('the mechanical git/GitHub work'). Binds FR-10, FR-11.
- (decision) The subagent ships as ONE CLI binary (single package.json bin entry, e.g. git-agent-subagent), internally routed by a subcommand argument (argv[2]) to per-action handlers (plan-commit, execute-commit, push, create-branch, draft-pr, create-pr, merge, finish-merge), mirroring how git itself is one binary with subcommands. Rejected alternative: one separate compiled binary per skill/flow, which would duplicate the no-force-push hook setup and query()/SDK wiring across files. Binds: all skill<->subagent invocation, FR-6 (single place the hook lives).
- (decision) Skill<->subagent invocation contract per flow (call count varies by whether a plan needs user approval before acting): create-branch=1 call (create-branch, no plan needed, type/task/description already decided in skill conversation); commit=2 calls (plan-commit returns commits[]+localOnlyCandidates[], skill collects all user decisions via AskUserQuestion relaying raw decisions never editing the plan, execute-commit takes original plan + decisions); push=1 call (push, hook-enforced no-force); create-pr=2 calls (draft-pr returns title+body, skill lets user edit, create-pr takes final title/body/target); update-branch=1 call if clean merge, 2 if conflict (merge returns ok or conflict+files, user resolves manually outside agent, finish-merge commits the resolution); configure=0 calls (direct file I/O in skill, no subagent). All calls exchange JSON: input via stdin/--input flag, output as the subagent's single final stdout JSON line.
- (version) Stack pinned: TypeScript on Node.js; @anthropic-ai/claude-agent-sdk (npm, confirmed current/actively published, latest 0.3.282 as of 2026-09-27) for the subagent program; requires the claude CLI (@anthropic-ai/claude-code) installed locally as the SDK's execution backend, which is also how auth is reused with no separate credential store. Distributed as an npm package installed via npx (author's own GitHub repo, not a marketplace plugin, per PRD 4.6).
- (decision) Response envelope convention: every subagent JSON response has top-level ok:boolean. On failure: reason:string, a stable machine-readable code (e.g. 'conflict', 'non-fast-forward', 'branch-exists'), plus optional detail fields (e.g. files:[]). On success: ok:true plus action-specific payload fields alongside it. Subcommand naming: verb-first kebab-case (plan-commit, execute-commit, create-branch, push, draft-pr, create-pr, merge, finish-merge).
- (decision) Design paradigm: Orchestrator/Worker. Skills (running as native Claude Code skills inside the user's interactive session) are the orchestrator -- hold conversation, state, all user interaction (AskUserQuestion), and own the plan-decision merging. The subagent CLI is a single stateless worker: invoked per-action as a fresh subprocess, no memory between calls, carries its own tool access and PreToolUse hook policy in its own SDK options code.
