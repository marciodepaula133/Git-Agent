- (note) Distilled from PRD FR-3/FR-4/FR-5 and architecture AD-1/AD-6/AD-9, cross-referenced against docs/initial-guidelines.md and the architecture spine (both adopted companions)
- (capability) CAP-1: propose a multi-commit plan splitting unrelated changes, including splitting within one file by line range (FR-3)
- (capability) CAP-2: ask about each local-only-looking file (e.g. .env-style) before committing rather than deciding silently (FR-4)
- (capability) CAP-3: follow the target repo's own commit template when configured, else a documented default (FR-5)
- (constraint) Local-only detection is owned solely by the subagent's plan-commit action via a fixed, extensible filename-pattern heuristic (.env, .env.*, *.pem, *.key, credentials*, secrets*, *.local); the skill never scans the working tree itself (AD-9)
- (constraint) No commit happens on a plan the user hasn't confirmed
- (constraint) execute-commit commits using the verbatim hunks from the original plan (snapshot-replay), never a fresh re-diff, even if the tree changed meanwhile (AD-9)
- (constraint) Two-call shape: plan-commit, then user decisions relayed raw and unedited, then execute-commit (AD-1, AD-6)
- (non-goal) Does not auto-exclude or auto-.gitignore local-only files; v1 only asks
- (non-goal) Does not write or edit code content
- (question) How is subagent plan quality (a 'good' commit split) verified beyond repo-state checks? Left open for implementation time (PRD Open Question 3)
