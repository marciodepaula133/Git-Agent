- (note) Distilled from PRD FR-10/FR-11/FR-12 and architecture AD-6/AD-8, cross-referenced against docs/initial-guidelines.md and the architecture spine (both adopted companions)
- (capability) CAP-1: npx first-run setup asks for default task/branch types and a default PR target branch, writing them to a per-repo config file; re-running against an already-configured repo asks for confirmation before overwriting (FR-10)
- (capability) CAP-2: every skill needing task/branch types or a default PR target reads them from the config file rather than hardcoding values (FR-11)
- (capability) CAP-3: a configure skill lets the user redo the config surface on demand, showing current values first, without re-running the npx installer (FR-12)
- (constraint) Config file is read/written directly by skills; the subagent never touches it (AD-8)
- (constraint) No subagent call for configure: direct file I/O in the skill (AD-6)
- (non-goal) No broad, general-purpose configurability; v1's surface is deliberately limited to task/branch types and default PR target
- (non-goal) No centrally managed / team-wide configuration; v1 is per-repo, self-serve only
- (assumption) Re-running the installer against an already-configured repo asks for confirmation before overwriting, rather than silently overwriting or refusing (PRD Assumptions Index, formerly Open Question 4, confirmed during architecture)
- (event) Pass 1 (coherence) and Pass 2 (preservation) both pass; SPEC.md rendered with 3 capabilities, 1 assumption, 0 open questions
